# ADR 0009: Fixed Diagnosis SLA and Append-only Assignment History

- Status: Accepted
- Date: 2026-07-17

## Context

诊断中心已有状态流转和首次自动认领，但缺少统一优先级时限、逾期视图和显式转派。若只在前端临时计算截止时间，列表、Dashboard 和审计会产生不同口径；若只覆盖当前负责人，事故交接过程又无法追溯。

## Decision

在诊断创建时使用观察时间和严重级别计算固定 `sla_due_at`：critical 1 小时、high 4 小时、warning 24 小时、info 72 小时。逾期不单独持久化，而是在查询时由数据库时钟、当前状态和截止时间计算。只有 open/confirmed 计入逾期；解决或驳回停止计入，重新打开沿用原截止时间。

当前负责人保存在诊断主记录，首次状态操作自动认领或显式转派时，在同一数据库事务内追加 `diagnosis_assignments`。历史同时保存用户外键和名称快照。转派目标仅允许活跃的系统管理员或运维管理员，重复转给当前负责人视为冲突。所有显式转派尝试继续进入平台审计，但审计层不保存备注正文。

## Consequences

- API、Dashboard 与诊断列表共享同一逾期口径。
- 负责人交接具有完整前后关系，用户删除后仍可解释。
- 重新打开不会通过重置 SLA 掩盖超时事实。
- 当前时限是平台固定策略，尚不支持租户、规则或维护窗口级定制。
- 查询使用数据库 `NOW()`；多实例部署需保证数据库时钟可靠。

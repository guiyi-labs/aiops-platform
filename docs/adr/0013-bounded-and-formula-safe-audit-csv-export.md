# ADR 0013: Bounded and Formula-safe Audit CSV Export

- Status: Accepted
- Date: 2026-07-17

## Context

安全审计员需要把筛选后的操作记录用于离线复核和论文实验留档。直接把数据库查询无限制流式写出会放大内存、连接和响应时间风险；把操作者、资源名、请求 ID 或 User-Agent 原样写入 CSV，则可能在 Excel 等软件中触发公式注入。导出行为本身也是敏感数据读取，必须可追溯。

## Decision

新增 `GET /api/v1/audit-logs/export`，沿用列表的集群、操作和结果筛选，并保持系统管理员/安全审计员权限。默认和最大导出量为 5000 行；服务先完成有界查询和内存编码，成功后一次性写入响应。响应头公开本次行数、匹配总数与截断状态，调用方可增加筛选后继续导出。

CSV 使用固定 15 列、UTC RFC3339 时间、CRLF 和 UTF-8 BOM。所有字符串先检查首个非空白字符，以 `=`、`+`、`-`、`@` 开头时在原值前添加单引号。导出只使用已脱敏的审计模型，不重新读取业务请求体或凭据。

导出路由显式加入统一审计映射，操作代码为 `audit.export`。中间件在文件响应完成后追加记录，因此导出可追溯，又不会把自身记录混入正在生成的文件。

## Consequences

- 常用电子表格软件可以直接识别 UTF-8 内容，同时公式型文本不会被当作活动公式。
- 5000 行上限保证单次数据库和内存成本有界，但大规模取证需要按条件拆分多次导出。
- CSV 包含来源地址和 User-Agent 等现有审计可见字段，文件离开平台后的存储和访问控制由使用者负责。
- 当前文件未做数字签名或加密；完整性签名、归档分区和保留策略仍属于后续工作。

# ADR 0014: Live Authorization and Safe User Lifecycle

- Status: Accepted
- Date: 2026-07-17

## Context

系统管理员需要在控制台创建账号、调整角色和停用访问。只依赖 JWT 签发时的角色会使撤权延迟到访问令牌过期；只在应用层先查询“管理员数量”再更新，则会在两个管理员并发互相降权时产生竞态，可能留下无人可管理的平台。

## Decision

访问令牌保留用户 ID 作为身份声明，但所有受保护请求都从 PostgreSQL 读取用户当前状态、显示名和角色后再授权。停用用户立即返回 403；角色被移除后，旧访问令牌在下一次请求时失去对应权限。角色更新或停用还会在同一事务中撤销该用户的有效刷新令牌。

用户管理仅对 `system_admin` 开放。领域层校验小写安全用户名、至少 12 字符的初始密码、显示名和预置角色，并使用 bcrypt 保存密码摘要。当前用户不能停用自己或修改自己的角色。

更新事务通过固定 PostgreSQL advisory lock 串行化所有系统管理员资格变更，锁定目标用户后计算更新结果；如果操作会移除最后一个活跃系统管理员，则返回 `LAST_SYSTEM_ADMIN` 并回滚。用户名唯一约束处理并发创建冲突。

## Consequences

- 停用和撤权无需等待访问令牌过期，权限状态与数据库一致。
- 用户每次认证请求增加一次数据库读取；后续如引入缓存，必须提供可靠的撤权失效机制，不能牺牲即时性。
- 单数据库事务同时覆盖用户、角色和刷新会话，但访问令牌本身无服务端黑名单；即时撤权依赖认证路径的实时查询。
- advisory lock 是 PostgreSQL 相关实现，未来更换数据库需要提供等价的全局串行化或不可破坏约束。
- 当前不包含密码重置、MFA、SSO/LDAP 或会话设备管理。

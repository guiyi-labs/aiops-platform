# ADR 0015: Versioned Credential Invalidation

- Status: Accepted
- Date: 2026-07-17

## Context

管理员重置用户密码后，仅撤销刷新令牌仍会让已经签发的访问令牌在最长 15 分钟内继续工作。使用“密码修改时间”与 JWT 秒级 `iat` 比较会在同一秒重置和重新登录时出现精度边界，也难以清晰表达多次重置顺序。

## Decision

为 `users` 增加从 1 开始的单调递增 `auth_version`。访问令牌签发时复制当前版本；认证中间件加载当前用户后必须同时验证状态和版本。版本不一致统一视为无效访问令牌。

系统管理员可以为其他用户提交 12–128 字符的新密码。仓储在同一 PostgreSQL 事务中更新 bcrypt 摘要、使用 `auth_version = auth_version + 1` 原子递增版本，并撤销该用户全部有效刷新令牌。管理接口禁止操作者重置自己的密码，避免响应后当前管理流程突然失效；个人密码修改应使用后续独立流程并明确重新登录交互。

## Consequences

- 数据库提交后，旧访问令牌、刷新令牌和旧密码全部失效。
- 每次认证原本已经读取当前用户，因此版本比较不增加额外查询。
- 部署迁移后，旧格式访问令牌因版本为 0 而失效；未被密码重置的刷新会话仍可换取新格式令牌。
- 凭据版本不暴露在用户管理响应，也不进入审计详情。
- 当前只支持管理员重置他人密码，不包含邮件找回、一次性链接、强制首次改密或用户主动改密。

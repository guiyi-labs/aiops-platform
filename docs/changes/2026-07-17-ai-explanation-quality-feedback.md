# 2026-07-17 AI Explanation Quality Feedback

## Scope

- 新增 `000010_ai_explanation_feedback`，保存三档质量结论、操作者名称快照和可选备注，并以数据库唯一约束限制单用户单解释一次评价。
- 解释历史新增 `feedback_summary` 与当前用户隔离的 `my_feedback`。
- 新增 `POST /api/v1/ai/explanations/{id}/feedback` 和 `GET /api/v1/ai/quality`。
- 所有登录角色均可评价；重复、非法和不存在解释分别使用 409、400、404 独立错误码。
- 全局质量汇总统计反馈总量、严格有帮助率、贡献者、已评价解释数和按模型分组。
- 反馈提交进入统一审计，备注不进入审计详情。
- 诊断页面新增三档评价、可选备注、个人评价锁定、单条解释统计和全局质量统计。

## Verification

- Go 聚焦测试覆盖反馈校验、个人评价上下文、质量汇总与审计路由；最终 `go test ./...` 和服务端构建通过。前端类型检查、7 个 Vitest 文件共 17 项测试及生产构建通过。
- PostgreSQL 真实应用 `000010`，表级校验、外键、单用户唯一约束和两个查询索引均存在。
- 系统管理员首次评价返回 201；重复评价返回 409 `AI_FEEDBACK_EXISTS`，非法结论返回 400 `INVALID_AI_FEEDBACK`。
- 只读用户成功提交独立评价，证明质量反馈不依赖诊断处置权限。
- 两位用户形成 1 条 `helpful`、1 条 `partially_helpful`，全局和按模型汇总均返回总数 2、有帮助率 0.5、贡献者 2。
- 解释列表分别返回登录用户自己的 `my_feedback`，同时只公开聚合计数；成功、重复和非法提交均产生对应 success/failure 审计。
- 浏览器验证未评价时显示三档按钮和备注输入；提交后立即显示个人评价并将全局/单条统计由 1 条 100% 更新为 2 条 50%。

## Boundaries

- 当前不支持撤回、改票、管理删除或评价争议流程。
- 汇总是原始人工样本，不自动选择模型、调整提示词或改变规则。
- 尚未实现按时间窗口、规则类型、集群或提示词版本的质量趋势分析。

# 2026-07-17 Audit CSV Export

## Scope

- 新增受系统管理员和安全审计员保护的 `GET /api/v1/audit-logs/export`。
- 复用集群、操作和结果筛选，默认/最大导出 5000 行，并返回行数、总数和截断响应头。
- 输出固定 15 列、UTC RFC3339 时间、CRLF 与 UTF-8 BOM。
- 对首个非空白字符为 `=`、`+`、`-`、`@` 的文本添加安全前缀，防止 CSV 公式注入。
- 导出只使用现有脱敏审计模型，不包含请求体、令牌、Cookie、kubeconfig 或 AI 上下文。
- 导出行为以 `audit.export` 记录 success/failure/denied。
- 审计页面增加完整操作筛选项、CSV 导出按钮、导出行数和截断提示。

## Verification

- Go 聚焦测试覆盖稳定列、BOM、公式中和、行数/截断结果、响应头和审计操作映射；最终 `go test ./...` 与服务端构建通过。
- 前端类型检查、7 个 Vitest 文件共 18 项测试及生产构建通过，覆盖筛选参数、文件名和导出元数据。
- 真实 PostgreSQL/API 验证筛选后仅导出 1 条目标记录，`X-Audit-Export-Rows/Total/Truncated` 为 `1/1/false`，文件名为 UTC 时间戳。
- 实际响应首字符为 U+FEFF；以 `=` 开头的操作者、`@` 开头的资源和 `+` 开头的请求 ID 均被单引号中和。
- 系统管理员与安全审计员返回 200；只读用户返回 403，匿名请求返回 401，`limit=5001` 返回 400。
- API 权限矩阵产生两条 success、两条 denied 和一条 failure 的 `audit.export` 记录；页面导出另追加一条 success。
- 浏览器验证操作/结果筛选、唯一结果、导出按钮和“已导出 1 条审计记录”反馈，页面无运行错误。

## Boundaries

- 单次最多导出 5000 行，不提供游标式批量归档。
- 文件没有签名、加密、保留标签或自动上传能力。
- 下载后的文件不再受平台 RBAC 控制，使用者必须按安全制度保存。

# m102-demo-drill：可复现闭环演示（登录→态势→根因→证据→受控动作→验证→事故复盘）

- Date: 2026-08-12
- Status: Complete
- Scope: M102「形成可复现演示」本地轨道——在完全隔离的离线 compose 环境中，用平台真实 API 串起「登录 → 态势 → 根因 → 证据 → 受控动作 → 验证 → 事故复盘」全链路，由仓库内 mock Kubernetes API 提供确定性集群对象。

## Context

M102 范围要求「形成可复现演示：登录 → 态势 → 根因 → 证据 → 受控动作 → 验证 → 事故复盘」。既有 `scripts/demo-up.ps1` 依赖 pwsh + kind（本机无 pwsh/kind，Docker Hub 不可达），无法在本机复现；同时诊断/受控动作必须命中真实集群 API，而本机没有可用集群。因此新增：

- 一个**离线 mock Kubernetes API 服务**（`backend/cmd/demo-kube-mock`），模拟平台演示旅程所需的最小 API 面（`/version` 探活、nodes、namespaces、pods、events、deployments、replicasets、metrics），提供确定性 fixture（Node `demo-node` Ready=False + 压力条件、Pod `demo-pod` 容器 OOMKilled + 警告事件、Deployment `demo-app` selector 匹配 pod 标签）；PATCH 变更（rollout restart / scale / image update / cordon）按 strategic-merge 语义合并进内存存储并记录 mutation，供演练验证「受控动作真的落在集群上」。
- 一个 **bash 版可复现演示脚本**（`scripts/demo-drill.sh`），复用 M102 双环境演练的隔离 compose 布局（独立 project/端口 21432/21080/21081/卷/网络，与开发栈 15432/8080/18080 及双环境演练 25432+ 零共享），驱动平台真实 API 完成全链路并落确定性报告。

## What Changed

### 新增：mock Kubernetes API 服务
- `backend/cmd/demo-kube-mock/main.go`：HTTPS 服务（启动时自签证书，供 `insecure-skip-tls-verify` 注册），`-listen` / `-healthcheck` 参数；与 `cmd/oidc-provider` 同为演练/开发工具，绝不作生产 Kubernetes API。
- `backend/cmd/demo-kube-mock/handler.go`：路由 + 内存存储；GET/PATCH nodes、pods、deployments、events、namespaces、replicasets、metrics、`/version`、`/api`、`/apis`、`/mock/mutations`；PATCH 支持 `dryRun=All`（不持久化）、uid/resourceVersion 冲突 409；`/mock/mutations` 返回已记录的变更。
- `backend/cmd/demo-kube-mock/fixtures.go`：确定性 fixture 对象，字段形状对齐平台 `internal/kubernetes` gateway 消费的 Kubernetes JSON 契约。
- `backend/cmd/demo-kube-mock/handler_test.go`：6 个单元测试（version/health、nodes、pod OOMKilled 证据、deployment restart dry-run 不持久化 + 真实 patch 持久化 + mutation 记录、409 冲突与 404、node cordon patch）。

### 新增：可复现演示脚本
- `scripts/demo-drill.sh`：完整旅程 15 项断言——
  1. install：隔离栈安装（pg 21432 / backend 21080 / frontend 21081），backend `health/ready`；
  2. login：frontend 200、admin 登录、`/me` → `system_admin`；
  3. cluster-register：注册 `demo` 集群（kubeconfig 指向 `https://demo-mock:8443`，insecure-skip-tls-verify + token），enable + probe → ready；
  4. situation：`/fleet/health` + `/clusters/:id/nodes` 可见 `demo-node`；
  5. root-cause-node / root-cause-pod：确定性诊断 `node.not_ready.v1`（critical）与 `pod.oom_killed.v1`（critical）；
  6. evidence-node / evidence-pod：证据、根因、建议非空，Pod 含 `container_termination` 证据；
  7. action-confirm / action-preview / action-execute：诊断确认 → remediation preview（`deployment.rollout_restart`，返回计划 + confirmation token）→ 携带 `Idempotency-Key` 执行 → `succeeded`；
  8. action-verify：mock `/mock/mutations` 记录真实 PATCH（`k8s-aiops.local/restarted-at` + `remediation-id`），平台 deployment 视图正常；
  9. incident-create / incident-journey：事故工作区创建 → confirmed → note → resolved → postmortem → CSV export（`number,title,source_type,...`）→ summary；
  10. cleanup：`down -v` 无残留。
- mock 镜像构建：宿主机 `CGO_ENABLED=0` 交叉编译（arm64/amd64 按 docker 引擎架构自动选择）+ `FROM scratch` 封包，仅本地已有镜像，离线可复现。

## Risks / Notes

- mock 服务仅覆盖演示旅程涉及的 API 面，未知路径返回 Kubernetes 风格 404；不模拟完整 Kubernetes 行为（如 admission、watch、分批滚动状态），不得用于承载真实工作负载的验证。
- 演示使用平台真实 API 与真实 PATCH 链路；受控动作落在 mock 集群（演练环境）上，属 M102 本地证据，不作为生产安装/运维声明。
- M102 仍要求 Gate A–D、两次组织全新环境演练、零未解释 critical、M89/M90 完成；M89/M90 仍为组织授权阻塞，版本保持 RC，不宣称 GA。

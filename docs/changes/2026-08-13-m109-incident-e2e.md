## Context

M109 路线图（`docs/development-roadmap-post-m106.md` §4）要求 incident 关键旅程 E2E 覆盖 Desktop/Mobile、axe、console error 断言。既有 `incidents.spec.ts` 已覆盖创建→移交→备注→确认→解决→复盘→reopen 全旅程，但 axe 扫描路由不含 `/incidents`（也不含 M108 新增的 correlation 视图），且 M108 的 `?case_id=` 深链聚焦与「提升事故」按钮、SOURCE_ALREADY_USED 去重分支均无浏览器级断言。

## What Changed

### E2E 覆盖扩展

- `frontend/e2e/a11y.spec.ts`：`scannedRoutes` 增加 `/incidents` 与 `/aiops/correlation`（空态 + `mockAuthenticatedAPI`），axe wcag2a/aa 0 critical/serious 断言覆盖这两条新路由。
- `frontend/e2e/correlation.spec.ts`（新）：
  - `?case_id=42` 深链聚焦：详情面板显示 `CASE #42`、主资源 `Pod/web-0`、信号链路（`sig-oom-1`/`kubelet`），「提升事故」按钮可用。
  - 提升事故：POST `/api/v1/incidents`（correlation 来源）→ 通知「已创建事故工作区 INC-000009」+ 详情徽章「已关联事故 INC-000009 ↗」；点击徽章跳转 `/incidents`（双向深链回程）。
  - 去重分支：POST 返回 409 `SOURCE_ALREADY_USED` → 稳定提示「该关联案例已存在关联的事故工作区」且不渲染已关联徽章。
  - console error 严格断言：除 Chromium 对预期 409 自动记录的 "Failed to load resource"（有意过滤）外，其余 console error = 0。

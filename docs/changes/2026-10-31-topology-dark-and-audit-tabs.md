# 拓扑图暗色可读性 + 审计盲区修复（2026-10-31）

## 起因

上一轮交付时把「暗色主题未覆盖图表与拓扑图的内部绘制颜色」写成了一条已知限制，
理由是「这些颜色写在 JS 里，不在 CSS 里」。本轮决定先量再判断，结果它不是"待办"，
而是**接管不过的缺陷**：

| 元素 | 实际颜色 | 背景 | 对比度 |
|---|---|---|---|
| 资源名（`.node-name`） | `#1d2226` | `#0d1315` | **1.2:1** |
| 节点类型（Node） | `#374151` | `#0d1315` | **2.0:1** |
| 命名空间（`.node-ns`） | `#6b7280` | `#0d1315` | 3.9:1 |
| 边标签（`.edge-label`） | `#6b7280` + 白底片 | `#0d1315` | 白块刺眼 |

也就是说：**切到暗色后，拓扑图上的资源名几乎完全看不见**。而 axe 一直报 0 违规。

## 为什么审计没抓到（这才是根本问题）

`scripts/audit-a11y-dark.mjs` 只做「goto 路由 → 跑 axe」，从不点 tab。拓扑图挂在
`/aiops/overview` 的第三个 tab 里，不点击时 DOM 里根本没有那些 `<text>` ——
**axe 扫的是一个不含拓扑图的页面**，自然报 0。

这不是漏了一个页面，而是审计方法本身的缺口：任何 tab / 折叠面板里的内容都在盲区里。

修法：`VIEWS` 支持第三项「需要逐个点开的 tab」，并在点击后重新扫；找不到 tab 时
计为 1 项违规并打印提示，避免哪天 tab 改名后审计悄悄退回盲区。

## 修法：SVG 的颜色必须走自定义属性

`fill` / `stroke` 写在属性里，不继承 `color`，所以写死十六进制就永远不跟主题走。
新增 13 个 `--topo-*` 变量，`console-theme.css` 的 `:root` 与 `.theme-dark` 各一套：

- **明色**：尽量引用已有调色板（`--blue-500` / `--gray-500` / `--status-success` 等），
  只有调色板里没有同值项的四个色相（Ingress 紫、StatefulSet 橙、DaemonSet 红、
  ReplicaSet 青、Namespace 蓝灰）保留字面量。写死同值字面量会被 token 门禁拦下，
  这个门禁在这里起了正面作用。
- **暗色**：色相不变、明度整体提亮（如 Node `#374151` → `#94a3b8`）。

节点色表从十六进制改为 `var(--topo-deployment)` 这类引用；边、箭头 marker、
边标签底片、三处文字色（名称/命名空间/边标签）一并改为变量。

## 顺带：33 条边交叉成一片，做了悬停高亮

节点按资源类型分列排布，33 条边必然交叉。全亮度下整张图糊成一片，颜色再准也读不出
"这条线连到哪"。给 `LayoutEdge` 补上 `sourceKey` / `targetKey`，悬停节点时：

- 与它相连的边保持原样，其余 `stroke-opacity: 0.07`
- 非相邻节点淡到 `opacity: 0.32`
- 默认就把边压到 `stroke-opacity: 0.55`

一个细节：**箭头是 `<marker>` 里的独立图元，不受 `line` 的 `stroke-opacity` 影响**。
只改透明度会在淡出的边上留下一片漂浮的小三角，必须同时 `marker-end: none`。

实测（悬停 `web-2`）：33 条边中 31 条淡出、22 个节点中 19 个淡出，移开鼠标后全部复原。

## 已知限制（更新）

- 悬停高亮只对鼠标有效。触屏上没有 hover，移动端仍只能靠颜色区分类型。
  真正的解法是点选节点后固定高亮，需要引入选中态与键盘可达性，本轮未做。
- 拓扑图按类型分列，边仍是直线。数据量再大（>100 节点）时应换成力导向布局或分层布局。

## 追加：全路由亮块扫描，揪出 `.service-icon`

拓扑修完后做了一次系统扫描：遍历 35 个真实路由，在暗色下找「背景亮度 > 200 的元素」。
命中 `.service-icon`（`rgb(233,251,248)`），出现在 SLO / 关联案例 / 自动化 / 质量四页。

根因与拓扑图同类但方向相反：它用的是 `var(--blue-50)` —— **调色板常量**。暗色主题
刻意不反转调色板（灰阶与蓝阶被大量直接引用，整体反转会让别处意外变色），所以写死
调色板背景的元素在暗色下会留下亮块。base.css 里另有一条同名规则用的是
`var(--accent-subtle)`，但 console-theme.css 后加载，还是调色板那条赢。

改为 `var(--accent-strong)` / `var(--accent-subtle)`。浅色下取值不变（第二处 `:root`
把这两个 token 定为同色），暗色下自动跟随。

### 一个操作教训

第一次扫描用的路由是 `/slo`、`/correlation` 这类——**它们不存在**，被
`{:pathMatch(.*)*}` 兜底重定向到首页。于是六个页面「无亮块」的结果其实是同一个首页，
扫描等于没做。真实路由是 `/aiops/slo`。凡是「批量扫页面」的结果，必须先确认每个
路径真的落到了目标页（比对标题或高亮菜单），否则很容易拿到一份漂亮的假结论。

### 复扫结果

- 35 个路由暗色亮块：**0**
- 12 个含 SVG 的页面，深色 SVG 文字（fill 亮度 < 90）：**0**

## 追加：浅色审计（ui-gate 第 3 步）也补上 tab

暗色审计补了 tab 之后，同一个盲区在 `ui-gate` 用的浅色审计里仍然存在——而它是
**门禁的一部分**，盲区留在门禁里比留在单独脚本里更糟。

`audit-a11y-axe.mjs` 走的是 CDP 直连（不是 Playwright），因此按同样方式补：
`views` 支持 `tabs` 字段，扫完首屏后逐个点击再扫，结果合并进同一个 violations 数组，
并在 id 后缀标注来源（如 `color-contrast @拓扑图`）。找不到标签页时同样计为一条
`tab-not-found` 违规，避免改名后静默退回盲区。

验证方式不是「跑通了就算」：用 Playwright 确认同一选择器命中 3 个标签页，
点击「拓扑图」后 `.page-content svg text` 从 0 变为 **99** 个节点——说明补扫的
确实是之前扫不到的那部分 DOM。

结果：浅色 axe 仍为 0 critical/serious，但覆盖面从 14 个状态扩到 17 个。

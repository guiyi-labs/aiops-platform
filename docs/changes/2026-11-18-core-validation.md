# Core Validation：规则验证、检索对比与诊断证据导出

- Date: 2026-11-18
- Status: Complete
- Scope: 将诊断与案例记忆的核心过程整合到现有工作区，保留五个一级入口。

## Context

规则引擎与混合检索已有后台实现，但界面主要展示最终结果，缺少输入、标注、召回来源与排名形成过程的可见证据。通过共享实际计算链路提供可复查的验证入口，避免引入无关业务模块。

## What Changed

- `backend/internal/diagnosisbench/`：从命令行评测器抽取固定语料与执行逻辑，Web 与 CLI 共享同一份 38 场景语料、规则函数和评估计算；增加逐场景原始输入、人工标签、目标规则输出与 Pod 优先级链结果。
- `frontend/src/views/DiagnosisValidationView.vue`：故障诊断新增“规则验证”页签，提供覆盖矩阵、TP/FP/FN/TN、精确率/召回率/F1、正负例筛选、原始输入、命中证据和 JSON 导出。
- `backend/internal/knowledge/{retriever,trace}.go`：同一次实际检索提供结构化短名单、向量召回、融合候选和最终结果。沿用正常检索的候选边界及降级语义，未另外实现一套模拟排名。
- `frontend/src/components/CaseRetrievalLab.vue`：历史案例增加“检索对比”，可从案例库带入参考案例，仅修改本次查询的规则提示观察更名后的召回差异；显示参考案例在基线/混合结果中的名次、阶段贡献、候选读取边界及真实降级状态，可导出已提交上下文和结果。
- `frontend/src/stores/case-comparison.ts`：仅在内存中保留参考案例，适配控制台按完整路由重挂载页面的行为。
- `frontend/src/views/DiagnosesView.vue`：增加当前已读取的诊断结论、结构化证据、AI 解释及回放快照导出。
- `frontend/src/composables/useResponsiveTables.ts`：允许矩阵表显式选择横向滚动，保留移动端列头与对照关系；滚动区域及 JSON 输入均可由键盘访问。
- HTTP 接口均需登录并记录审计；OpenAPI、生成类型、权限矩阵和共享界面审计目录同步更新。

## Risks / Notes

- 固定语料上的 38 场景、12 规则结果用于规格一致性回归，不代表生产准确率，不读写实际集群，不持久化诊断记录。
- 案例对比查询只读现有库，不修改规则或案例；使用默认高严重度范围、短名单与候选池上限；本次关闭模型重排以隔离召回和融合效果。
- 当前向量实现为 `lexical-hash-v1` 词法嵌入。排序分数不是诊断置信度；单个参考案例排名不等于整体检索命中率。候选池达到上限和向量不可用时均有明确说明。
- 证据导出仅包含已读取的数据及可用性标记，不补造缺失证据，不自动调用模型。
- 本次仅本地归档，不推送远端；现有集群、数据库与用户数据保留。
